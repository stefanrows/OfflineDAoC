# Trials of Atlantis: db-public dungeon spawns and ToA loot (WP1.1b)

Package WP1.1b of [TOA_PLAN.md](TOA_PLAN.md). Measured 2026-10-24 against a
copy of the dev snapshot; nothing here touched the live install. Background:
[TOA_RESEARCH.md](TOA_RESEARCH.md) (Supplementary sources) and
[TOA_IMPORT_PROBE.md](TOA_IMPORT_PROBE.md) (gaheris files, probe tool).

## Result

- **Three ToA dungeons get their spawns:** Sobekite Eternal, Temple of
  Twilight and Halls of Ma'ati, in all three realm copies. Cetus' Pit gets its
  boss Cetus and nothing else.
- **Deep Volcanus and Celestius stay empty.** db-public has no mob in regions
  46, 89, 146 or 91. The SWDB copy from WP0.1 has none either.
- **ToA mobs get their loot.** 2,106 loot rows in 363 templates, 1,625
  items. Every item already exists in our item table.
- **No duplicates, no broken references, no skipped classes.** Every row is a
  plain `DOL.GS.GameNPC`. A second application inserts nothing.

### Skipped ClassTypes

None. The generator would skip rows whose ClassType has no class in
`source/server` when the class is the NPC's function (teleporter, boat,
merchant, trainer, guard and similar, or any NPC with a merchant list), and
keep plain monsters on the server's GameNPC fallback. The dungeon rows contain
neither case.

### The "7 missing items" are a case difference

WP0.1 counted 7 loot items missing from our `ItemTemplate`, for example
`Spear_of_kings,_piece_1_of_3` against our `Spear_of_Kings,_piece_1_of_3`.
Our `Id_nb` column is `COLLATE NOCASE`, and `LootGeneratorTemplate` looks
items up with `ToLower()`. All of them resolve, so 040 adds no
`ItemTemplate` rows.

## Mapping rules (tools/toa/build_dbpublic_packs.py)

- **Columns.** Our column lists are hardcoded from `PRAGMA table_info` of the
  snapshot. Columns we lack are dropped and counted: only `Mob.MaxDistance`
  (2,135 rows). Columns db-public lacks, or leaves NULL where ours is NOT NULL,
  get our default: only `NpcTemplate.FactionID` (119 rows, 0).
- **Ids.** Mob_ID, NpcTemplate_ID, NPCEquipment_ID, LootTemplate_ID and
  MobXLootTemplate_ID stay as in db-public. Mob rows get PackageID
  `dbpublic-toa-dungeons` instead of db-public's `Toa_Hib`; inserted
  templates get the same tag.
- **Guards.** Mob: Mob_ID conflict, or a same-named mob of another package
  within 50 units in the region. NpcTemplate: the TemplateId exists.
  NPCEquipment: any row of that TemplateID exists, and a template never spans
  two statements. Faction: ID or Faction_ID conflict. LootTemplate and
  MobXLootTemplate: the same name pair exists. Statements are
  `INSERT … SELECT … FROM (VALUES …) WHERE … ON CONFLICT DO NOTHING`
  (SQLite 3.24 or newer).
- **Broken template links.** A mob is unlinked (`NPCTemplateID` 0) when its
  template has `ReplaceMobValues` set and the mob's own model is not among the
  template's models. Otherwise the template would turn it into another
  creature at spawn. This hits 3 rows: the Sobekite Eternal chess "Knight"
  (model 993), which db-public links to template 12967, a human Albion knight.
  The knight keeps its own level 47, model and equipment.
- **Loot names.** Mob names come from every db-public mob in regions 30-47,
  70-90, 91 and 130-147. That covers the overworld, the Havens, Aerus, the
  Pyramid, the dungeons and Celestius. 040 takes every LootTemplate row of a
  linked template, plus templates named after a ToA mob. The server drops
  those even without a link, which adds The Phoenix with 23 items.
  WP0.1's region set (without Aerus and the Pyramid) gives the 1,876 rows /
  341 templates / 1,423 items reported there. The wider set adds 230 rows.
- **Drop chances.** 2,055 of the 2,106 rows drop at 15 %, the rest at 2-20 %.
  None is 100 % or timed.

## Reproduce

From the worktree root. Downloads go to their own empty directory. Python
that reads them runs with `-I`.

```bash
# 1. db-public JSON (commit e0e6ed28…, 2026-10-22), into an empty directory.
DATA=/tmp/claude-1001/-mnt-c-OfflineDAoC/b910e783-6a50-46ab-9569-d34f347bae8d/scratchpad/wp11b/dbpub
mkdir -p "$DATA"
for f in Mob.0 Mob.1 Mob.2 Mob.3 Mob.4 NpcTemplate NPCEquipment Faction LootTemplate MobXLootTemplate; do
  curl -sSfL -o "$DATA/$f.json" \
    "https://raw.githubusercontent.com/Eve-of-Darkness/db-public/e0e6ed280f6239d2c40d4d0a57b244dafdc2056e/data/$f.json"
done

# 2. Generate 030, 031, 040 (about 20 s; the ClassType check scans source/server).
python3 -I tools/toa/build_dbpublic_packs.py --src "$DATA" --out tools/toa/sql \
  --source-ref e0e6ed280f6239d2c40d4d0a57b244dafdc2056e

# 3. gaheris file 13 (untracked, 11.6 MB), see tools/toa/README.md.
python3 -I tools/toa/convert_mysql_to_sqlite.py --src /mnt/c/OfflineDAoC-ext/gaheris/sql \
  --out tools/toa/sql 13-atlantis-mobs.sql
git checkout -- tools/toa/sql/conversion-report.json   # the single-file run rewrites it

# 4. Probe base: copy and repair the dev snapshot as in TOA_IMPORT_PROBE.md step 1.

# 5. Probe: gaheris first, then the packs, then the packs again (about 3.5 minutes on /mnt/c).
python3 -I tools/toa/probe_import.py --fresh-from .toa-probe/snapshot.clean.db \
  --db .toa-probe/probe.db --sql-dir tools/toa/sql --json .toa-probe/report-dungeons.json \
  12-master-levels.sql 13-atlantis-mobs.sql 14-atlantis-travel.sql 28-atlantis-portals.sql \
  29-atlantis-zonepoints.sql 35-atlantis-npcs.sql 36-artifact-scrolls.sql \
  39-master-level-paths.sql 42-master-levels-gaps.sql 43-master-levels-corrected.sql \
  031-toa-dungeon-templates.sql 030-toa-dungeon-mobs.sql 040-toa-loot.sql \
  031-toa-dungeon-templates.sql 030-toa-dungeon-mobs.sql 040-toa-loot.sql
# report keys: dungeon_regions_before/after, dbpublic_sanity

# 6. Unit tests.
python3 -m unittest discover -s tools/toa -p 'test_*.py'
```
