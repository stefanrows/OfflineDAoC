# open BG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A permanently open Thidranki battleground (region 252) with its own fixed bot crew, a phase cycle, roles, setup UI, scaled quests and guest squads, built in four deployable stages.

**Architecture:** Region 252 becomes a campaign definition of kind `Open` so the existing keep, landing, claim, quest and porter machinery works for it; everything open-BG-specific lives in new `OpenBattleground*` units (properties, roster, director, roles, guest squads, `/bgsetup`, launcher tab) and hooks into the driver's `Lead` and the participation admit/leave paths through a handful of small edits.

**Tech Stack:** C# .NET 10 server (`tools/dev/winnet.sh build|test`, NUnit tests under `source/server/Tests/UnitTests`), WinForms launcher, Detour navmesh builder (`tools/dev/build-battleground-nav.sh`), SQLite save (read-only via `playable-dev/dbquery.py`).

**Spec:** `docs/superpowers/specs/2026-10-11-open-bg-design.md`

## Global Constraints

- Owner decisions in the spec §2 are fixed; do not re-ask or change them.
- Cycle and relief timers run in game time (`GameLoop.GameLoopTime`), not wall-clock time; the night test runs at world speed 20×.
- Stefan's bracket campaign (regions 165, 234–242, 251) must behave exactly as before; every open-BG branch is keyed on `BattlegroundDefinitionKind.Open`.
- Never change a persistent bot's level, gear, guild or realm points; open-BG assignment state is in memory only.
- Server properties: prefix `open_bg_`, category `"pvp"`, defaults in the static class, clamped at use.
- Line endings: keep each file's existing style (`git diff --stat` must equal `git diff --stat --ignore-cr-at-eol`); new server files LF, launcher files as their neighbours.
- Builds via `OFFLINE_DAOC_ROOT=/mnt/c/OfflineDAoC/playable tools/dev/winnet.sh ...`; run only the touched test classes (the full suite has 8 known failures); `winnet.sh build-server shutdown` after each build.
- Agents never edit CHANGELOG.md, docs/BUGS.md, docs/TASKS.md or version pins; the orchestrator bumps once per shipped stage (MINOR).
- Logging keys: `OPEN_BG_UNAVAILABLE`, `OPEN_BG_ROSTER`, `OPEN_BG_RELIEF`, `OPEN_BG_PHASE`, `OPEN_BG_ROLE`, `OPEN_BG_GUEST`, `OPEN_BG_TICK_SLOW`, `OPEN_BG_SETUP`.

## Review Focus

1. A level-50 player with no bracket talks to a porter: `ForLevel` must not route them into the open BG by accident, and `[open BG]` must be the only way in (test in Task 2).
2. The open BG is enabled but zone 252 has no navmesh: the porter line is hidden, bots are never assigned, `OPEN_BG_UNAVAILABLE reason=no_navmesh` once (test in Task 3).
3. The roster's cap is lower than the setup sum (e.g. cap 24, setup 54): admits stop at the cap, no exception, `OPEN_BG_ROSTER` shows `cap=`, and relief still rotates (test in Task 5).
4. A human guild claims the keep: the director treats it as the owner, the push targets it, hold rewards go to the humans, and no bot "retreat" releases it (test in Task 7).
5. A level-12 player enters, logs out 2 min later: the guest squad despawns within 5 min and no non-persistent bot is ever saved (test in Task 11).
